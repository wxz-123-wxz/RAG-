# 项目约束与待确认事项

## 1. 已确认范围

- 题目暂定为“基于检索增强生成的高校软件工程专业知识问答系统设计与实现”。
- 首期面向软件工程课程，不扩展为开放领域问答平台。
- 三类角色：学生、教师/知识库管理员、系统管理员。
- 技术主线：Vue 3 + Spring Boot 3 + FastAPI + MySQL 8 + Elasticsearch；Redis 按实际需要使用。
- 首期文档格式：PDF、DOCX、Markdown、TXT。扫描 PDF 只提示暂不支持或解析质量有限。
- RAG 必须包含混合检索、可选重排序、引用溯源、证据不足拒答和离线评测。

## 2. 工作假设

| 编号 | 假设 | 影响 | 验证时点 |
|---|---|---|---|
| A-01 | 系统作为校内课程辅助工具，不保存敏感个人信息 | 可采用基础账号体系和逻辑删除 | 需求评审 |
| A-02 | 教师只管理被授权的知识库，系统管理员管理全局配置 | 决定数据权限模型 | 需求评审 |
| A-03 | 首期单文件上限暂定 50 MB | 影响上传、存储和超时配置 | 开发前 |
| A-04 | 一次问答只选择一个知识库 | 降低权限和引用归属复杂度 | 需求评审 |
| A-05 | 对话上下文默认取最近 10 轮，并在检索前进行问题改写 | 影响令牌消耗和多轮效果 | RAG 实验 |
| A-06 | 本地开发允许使用兼容 OpenAI 协议的生成模型接口 | 保持模型供应方可替换 | 开发前 |
| A-07 | 文档正文存工作区文件目录，业务元数据存 MySQL，检索索引存 Elasticsearch | 决定部署和备份方案 | 架构评审 |
| A-08 | 评测题由学生整理，至少部分由教师或同学复核 | 影响论文实验可信度 | 效果测试前 |

## 3. 用户与学校约束确认

用户于 2026-09-23 确认“无特殊要求，按当前方案继续”。据此，系统实现按本文既定范围和技术路线推进，论文工作暂不开展。以下项目状态为：

- [x] 学校/导师无额外题目、技术栈和论文格式约束。
- [x] 首期使用系统自有账号，不接入学校统一身份认证。
- [x] 首期以角色和知识库授权关系实现教师管理权限。
- [ ] 外部大模型 API 与答辩现场联网条件仍需在部署前确认。
- [ ] 课程资料必须在导入前逐份确认来源和授权状态。
- [ ] 最终部署机器的物理内存、GPU 型号和可用资源仍待确认。

## 4. 技术决策记录

| 决策 | 选择 | 理由 | 状态 |
|---|---|---|---|
| ADR-001 | 业务后端与 RAG 服务分离 | Java 负责权限和业务一致性，Python 负责模型生态 | 已采纳 |
| ADR-002 | Elasticsearch 同时承载 BM25 与向量索引 | 便于同库过滤、混合检索和结果解释 | 待原型验证 |
| ADR-003 | 使用 RRF 作为首版融合算法 | 参数少、对不同分数量纲不敏感，便于对比实验 | 待实验验证 |
| ADR-004 | 模型能力通过接口抽象 | 可切换本地模型与兼容接口，避免供应方绑定 | 已采纳 |
| ADR-005 | 文档处理采用异步任务 | 解析和向量化耗时，不阻塞上传请求 | 已采纳 |
| ADR-006 | 首期使用本地文件存储 | 项目规模可控，后续可替换 MinIO | 待部署确认 |

## 5. 变更规则

重大变更包括更换前后端技术栈、取消混合检索、取消评测模块、扩大到多专业或引入复杂 OCR。发生重大变更前应记录原因、影响和替代方案，并由用户确认。
