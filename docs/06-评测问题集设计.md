# 标准问题集与效果评测设计

版本：0.1

> 2026-09-24 交接说明：本文为早期设计，100 题模板尚不能视为人工审核金标准。当前实现中的“Recall@5”接近最终引用命中率，MRR 也不是完整检索候选排名指标。下一阶段按 [12-系统测试与RAG参数实验交接任务书-GPT5.6Luna.md](12-系统测试与RAG参数实验交接任务书-GPT5.6Luna.md) 的指标、题集分组与独立测试要求执行；不要直接用旧页面指标选择最佳切分/阈值。

## 1. 目的

标准问题集用于回答研究问题：与单一向量检索相比，混合检索和重排序能否提升软件工程专业问答的检索召回率、引用准确率和回答正确率。题集既用于参数调优，也用于最终测试，因此必须划分数据集并避免用测试集反复调参。

## 2. 100 题建议分布

### 2.1 课程分布

| 课程 | 数量 |
|---|---:|
| 软件工程导论 | 20 |
| 需求工程 | 16 |
| 软件设计与架构 | 16 |
| 软件测试 | 18 |
| 软件项目管理 | 15 |
| 敏捷开发与 DevOps | 15 |
| 合计 | 100 |

### 2.2 题型分布

| 题型代码 | 题型 | 数量 | 特征 |
|---|---|---:|---|
| `DEFINITION` | 定义查找 | 20 | 可从明确片段定位定义 |
| `EXPLANATION` | 概念解释 | 20 | 需要组织一个或多个相邻片段 |
| `COMPARISON` | 概念比较 | 15 | 答案包含至少两个对象及比较维度 |
| `PROCESS` | 流程说明 | 15 | 要求顺序、输入输出或角色信息 |
| `CROSS_SECTION` | 跨章节综合 | 10 | 需要两个及以上来源片段 |
| `OUT_OF_SCOPE` | 知识库外问题 | 10 | 应拒答，不设置伪标准答案 |
| `AMBIGUOUS` | 歧义/信息不足 | 10 | 应澄清或在依据不足时拒答 |
| 合计 | | 100 | |

CSV 模板已按上述题型数量和课程总量预置 100 行，但问题和标准答案必须基于最终授权资料填写，不能由系统凭空生成后直接当作金标准。

## 3. 字段规范

| 字段 | 必填 | 说明 |
|---|---|---|
| `question_id` | 是 | 稳定编号 `Q001` 至 `Q100` |
| `course` | 是 | 所属课程/知识库 |
| `question_type` | 是 | 上述受控代码 |
| `question` | 是 | 自然语言问题，不包含答案暗示 |
| `reference_answer` | 非拒答题必填 | 人工整理的标准答案要点 |
| `reference_document` | 非拒答题必填 | 文档的稳定名称和版本 |
| `reference_section` | 推荐 | 章节/标题路径 |
| `reference_pages` | 有页码时必填 | 如 `28-29`，无页码则留空 |
| `evidence_text` | 非拒答题必填 | 支撑答案的最小关键原文 |
| `should_refuse` | 是 | `TRUE` 或 `FALSE` |
| `review_status` | 是 | `DRAFT`、`REVIEWED`、`REJECTED` |
| `reviewer` | 复核后必填 | 教师/同学标识，不存无关个人信息 |
| `notes` | 否 | 歧义点、评分要求、资料限制 |

## 4. 编制流程

1. 建立资料清单，记录来源、授权、课程、版本和更新时间。
2. 逐份资料标注可出题章节，先摘录关键证据，再编写问题和答案。
3. 保持问题语言接近真实学生提问，避免全部复制章节标题。
4. 为比较题、流程题和综合题记录评分要点；为知识库外题记录拒答理由。
5. 由第二人抽查至少 20%，检查答案、证据定位和拒答标记。
6. 冻结题集版本，之后修改必须产生新版本并说明原因。

## 5. 数据集划分

- 开发/调参集：建议 30 题，用于切片、topK、融合权重和阈值选择。
- 测试集：建议 70 题，仅在方案固定后运行最终对比。
- 若必须展示完整 100 题结果，可同时报告全量结果，但论文主结论优先使用未参与调参的测试集。
- 三种检索方案必须使用同一知识库快照、同一题集版本和同一硬件环境。

## 6. 对比方案

| 方案 | 检索链路 | 主要控制变量 |
|---|---|---|
| E1 | 仅向量检索 | Embedding、topK |
| E2 | BM25 + 向量 + RRF | 两路 topK、RRF k/权重 |
| E3 | BM25 + 向量 + RRF + Reranker | 候选数、最终 topK、重排模型 |

生成模型、系统提示词、题集、知识库版本和证据预算保持一致，避免把生成模型差异误当作检索改进。

## 7. 指标定义

### 7.1 自动检索指标

- `Recall@5`：前 5 个结果中是否至少命中一个标注相关片段；多相关片段题可同时报告命中比例。
- `MRR`：第一个相关结果排名的倒数，未命中记 0。
- `P95 检索耗时`：同一测试环境下检索总耗时的 95 分位值。

“相关片段”不能只用文档名判断；应优先用人工标注的 chunk ID。切片配置改变导致 chunk ID 改变时，以证据文本重叠和人工映射生成该次运行的相关集合。

### 7.2 问答与引用指标

- 回答正确性：1-5 分，关键事实是否与标准答案一致。
- 完整性：1-5 分，评分要点覆盖程度。
- 引用准确率：回答中的事实性主张被所引片段支持的比例。
- 正确拒答率：应拒答题中实际拒答的比例。
- 无依据回答率：没有充分证据却生成事实性答案的比例。
- 端到端耗时：从业务后端接收问题到持久化完整结果。

人工评分应在不知道方案编号的情况下进行；至少抽取 20 题由两人独立评分并报告一致性或分歧处理方法。

## 8. 运行记录

每次评测必须保存：

- 运行 ID、题集版本、知识库与索引快照。
- 切片大小/重叠、Embedding、Reranker、生成模型及版本。
- BM25/向量候选数、RRF 参数、最终 topK、证据阈值。
- 每题候选排名、分数、答案、引用、拒答状态、阶段耗时和错误。
- 自动指标和人工评分，不得只保存汇总均值。
- CPU、内存、GPU、并发数、部署方式和网络条件。

## 9. 质量检查

- 问题不能依赖模板中未提供的隐含上下文。
- 标准答案不能比来源证据包含更多未经支持的事实。
- 知识库外题应真正不在资料范围内，不能仅因检索参数差而“找不到”。
- 歧义题应在备注中写明预期行为：澄清、列出可能解释或拒答。
- 同义改写题不得同时跨入调参集和测试集，防止数据泄漏。
- 任何未完成或失败题必须单独统计，不得从分母中静默删除。

## 10. 产出文件

- `data/evaluation/questions-template.csv`：100 题录入模板。
- 后续实现阶段新增版本化题集、逐题运行结果和人工评分文件。
- 论文中的表格和图应能追溯到一个或多个明确的评测运行 ID。
