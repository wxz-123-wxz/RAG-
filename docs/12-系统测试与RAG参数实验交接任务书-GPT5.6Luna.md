## 4. 实际执行路径：调参前必须核实

| 部位 | 当前代码与含义 |
|---|---|
| 生产切分入口 | `backend/src/main/java/com/graduation/ragqa/document/IngestionService.java` 中 `split(text, 600, 100)`；按换行回退边界 |

### 6.1 建议先保留的回归问题

- 定义与短问：`排序` / `什么是排序？`、`二叉树`、`死锁`、`B树是什么`。

- 同义与中英：二分查找/折半查找、B-tree/B树、TCP 三次握手、虚拟内存/虚存。
- 多证据：比较两种排序方法的稳定性/复杂度、组合多个章节或跨知识库的问题。人工确认哪些要点有依据。
- 历史切换：先问 Git 变基，再问 B 树；先问测试再问操作系统；具体新主题与明确代词追问分开测试。

## 7. 建立能用于实验的题集

### 7.1 持续发现问题：覆盖分类与变体测试

不能证明已找出“所有可能的问题”。目标是高风险行为有可执行检查、已发现错误不再反复出现、未知问题能留下定位证据。不要只继续随机提问。

1. **每个知识点建立一组不同说法**：正式术语、无歧义简称、问句/关键词、中英名称、标点空格、原理/复杂度/程序/比较等不同任务。人工确认前几类是否同义；任务不同不能强行要求同一答案。典型组为“冒泡算法/冒泡排序算法/什么是冒泡排序”。
2. **用相互关系检查结果**：真正同义问法应该命中同一证据组；换成无关问题不应继承上个主题；加入无关文档不应覆盖原有定义；重复片段不应重复计分；撤销权限后旧会话不能继续读新受限内容。答案文字可变，比较支持证据和行为，不要求字符串完全相同。
3. **按层记录故障**：无候选、过滤清空、证据选择缺要点、模型拒答、坏 JSON、编号越界、代码标记误判、超时和数据库失败分开。当前错误提示较粗，需要按最小修改增加受控诊断；不输出秘密或无关私人资料。
4. **受控构造边界输出**：模型替身返回空 citations、越界引用、代码 `arr[0]`、数字列表、未闭合代码块、坏 JSON、截断、401/429/超时等；普通知识库和 GENERAL 两条路径都测。替身只验证程序控制流，少量真实模型再验证接入，不能把两者混报。
5. **逐项积累而不是一次穷举**：每批补 10—20 个已审核样本；修一个缺陷，增加正例与可能误伤的负例，再复跑既有关键集合。依功能×角色×数据状态×模式做覆盖表，先测高风险组合和成对组合，不追求无上限全组合。
6. **从实际使用收集新样本**：记录完整问题、模式、检索范围、状态、错误码/trace ID、预期和实际；用户点“无帮助”的题进入待审核池。不要默默把所有用户原文长期写入日志，限定本地、必要字段及保留范围。
7. **每批交付可审阅结论**：新增发现数、已修/待修/未复现、覆盖缺口、误拒/无依据接收、故障数，附原始样本。近期不再发现问题只意味着在该覆盖范围内趋于稳定，不能宣称零缺陷。

### 7.2 题集规模、标注和划分

先用 **30—50 道人工核对的试验题**验证工具与指标，再扩展到约 **150—250 道**，按时间与审核能力分批完成。数量是工作建议，不是已经完成或必须凑满的成绩指标。

覆盖软件工程及 408 四科；包含完整可答、部分可答、无依据、词汇近似负例、同义改写、概念/比较/步骤/组合、多轮指代和噪声资料。每类数量和占比公开；不能只挑系统答得好的题。

每题至少保存：

```text
question_id, question, subject, question_type, scope, paraphrase_group
expected_boundary: complete | partial | insufficient
required_answer_aspects, unsupported_aspects
gold_evidence_groups: [evidence_unit_id, alternatives[source_hash, heading, start, end, quote]]
offset_unit, reviewer, review_status, split, notes
```

- 金标准锚定固定来源文本及 SHA-256、标题/章节、原文区间，而不是某一切分配置的 chunk_id。标注偏移采用规范化文本的 Unicode code point 时写清楚，并另存到 Java UTF-16 偏移的映射，不能混用。
- 一个知识要点可以有多处等价来源，标为同一证据组的替代项；同一段因重叠而产生的多个块只算一次。多个必须要点则分为不同组，才能衡量综合题召回。
- 预先规定“块是否覆盖证据”的判定规则；跨边界的两个块可以联合覆盖一个证据单位。不能仅共享一个词或命中文档标题就算相关。
- 冻结开发/验证/测试划分。可从 60%/20%/20% 起步，按主题、同义改写组和来源段落分组，避免同题换个措辞落入不同集合；分科/标签尽量均衡。
- 开发集调代码，验证集选参数，锁定测试集只做最终评估。若看了测试失败并据此改配置，应承认测试集已用于开发，再准备新的独立测试或明确探索性结果。
- AI 可起草题目与证据，但未经人工核对不能标为金标准。审题资源不足时先输出待审核题集，不把自评当人工验收。

## 8. 先修评测观测，再做参数实验

### 8.1 先保证能够观察每一层

为离线评测增加可选诊断输出，不影响普通用户界面，也不记录秘密。每题至少包含：原问题、改写问题、实际允许版本范围、各通道原始分数/排名、融合前后候选、主题过滤及原因、概念优先变动、实际送模证据、拒答发生层、生成引用和错误码。

当前代码只返回过滤后 top-k，不足以分析过滤误伤；先在测试工具或受控诊断模式记录过滤前候选。不要通过修改公共接口泄露用户无权访问的文档或调试内容。

固定完整配置快照：切分算法/单位/边界、来源与索引 hash、embedding 实例类型/版本/维度、BM25 参数、RRF/权重、各 k 的含义、门控开关/阈值、证据预算、模型 ID/提示 hash/调用参数、源码 hash、环境和时间。请求字段与最终生效参数不同要明确记录。

### 8.2 分阶段实验，避免全量笛卡尔积

| 阶段 | 建议比较 | 进入下一阶段的条件 |
|---|---|---|
| A：固定基线 | 当前 Java 600/100、哈希、混合 top5、现行门控/概念优先；离线复跑同一题集 | 参数可追溯、检索排名可复算、失败样本保留 |
| B：切分粗筛 | 长度 300/600/900/1200 UTF-16 单位 × 重叠 0%/10%/20%，加上准确基线 600/100；最多 13 组 | 独立索引、同一语料与模型、同一题集；报告实际块数和长度分布，不只参数名 |
| C：切分细化 | 仅对 B 阶段较好的 2—3 组比较按标题/段落结构切分；先保护定义、列表、代码块的边界 | 结构规则有真实实现与生产路径一致性测试 |
| D：检索与证据预算 | top_k=3/5/8；融合权重或单通道消融一次改一项；当前生成证据上限 5 必须明确 | 区分检索 top-k 与实际送模 k；用于生成比较时显式配置证据预算并记录截断 |
| E：门控阈值 | 对已选配置，在验证集分布上扫描少量候选阈值，比较误接收/误拒答 | 明确哪条分支实际使用该阈值；门控前后效果均有数据 |
| F：少量生成复核 | 只对基线和候选配置的小样本做真实生成，检查相关性、证据支持、部分覆盖与延迟 | 离线结果先通过；默认本阶段先限制 20 次新外部调用，逐次计数，不自动扩大预算 |

本阶段默认先做 A 和试验题集。不要一次运行 B—F 的所有组合。候选召回数 10/20/40 只在实际存在独立召回/重排阶段时使用；当前全量评分路径不能仅添加一个配置字段就宣称完成该实验。

切分比较有两种不同问题：固定 k 的真实行为比较，以及固定上下文 token 预算的公平比较。两者分别报告，不能把大块因上下文更多获得的收益完全归因于切分策略。无可用精确 tokenizer 时报告字符数与估算方法，不伪称精确 token 数。

真实中文 Embedding 和 Reranker 是另一个后续实验阶段。先确认许可证、硬件、磁盘、下载大小与授权，再实现真实 provider、独立索引、模型身份记录和验证。模型/维度/文本预处理改变必须重建相应实验索引并重新标定；不能混用旧向量。不要同时更换模型、切分、重排和提示后声称识别了某个参数的作用。

### 8.3 阈值的实验要求

- 余弦、BM25、RRF 与未来 reranker 分数不是同一量纲，也不是概率；不能直接套 0.6/0.8。
- 当前 HYBRID 的 BM25 正分分支能绕过向量阈值。因此仅扫描 evidence_threshold 可能完全不改变结果；必须记录每题门控分支与配置敏感性，不能把无变化当“阈值稳定”。
- VECTOR 路径也有主题门控，不能当作纯语义模型性能。对门控消融仅在隔离实验中做，不能直接关闭现用保护。
- 验证集上分别观察可答、部分可答、不可答分布与混淆矩阵。阈值选择同时考虑无依据接收和有依据误拒绝，不单纯最大化拒答率。
- 先公布比较目标、权衡原则和相对基线可接受的退步范围，再观察结果；不能看完测试结果后倒推标准。没有显著或稳定收益时保留基线也是合格结论。
- 以问题组为单位计算区间或重复抽样，不能把同义题/重叠块当相互独立的多个成功样本；小样本结论标明不确定性。

## 9. 指标必须能从逐题数据复算

以下在正例且人工有证据标注的题上计算；无定义的分母输出 null/不适用，并报告有效样本数。

| 指标 | 定义与注意事项 |
|---|---|
| Hit@k | 前 k 个检索块是否覆盖至少一个金标准证据组，逐题 0/1 后取均值；不能称为多证据召回率 |
| Evidence Recall@k | 前 k 个块覆盖的必需证据组数 / 该题全部必需证据组数；一个组有多个替代来源只计一次；报告逐题宏平均与分科结果 |
| MRR@k | 前 k 个真实检索候选中第一个满足相关判定的排名 r，取 1/r；未命中为 0。不能用模型最终引用顺序代替检索排名 |
| 过滤影响 | 分别计算门控前、门控后、最终送模证据的 Hit/Recall；说明缺失发生在哪一层 |
| 误拒答率 | 完整可答题中被 REFUSED 的比例；部分可答题单列，不能混成一个正例类别 |
| 无依据接收率 | 无依据题中系统仍以知识库答案回答的比例；超时/报错单列，不算正确拒答 |
| 覆盖标签 | 人工 complete/partial/insufficient 与模型标签的混淆矩阵；模型自报完整不是正确答案金标准 |
| 引用支持 | 人工逐条核对实质性论断是否被其引用支持；引用有效性、语义支持精度、该引用却未引用的论断覆盖率分别统计 |
| 任务回答质量 | 对实际提问的要点覆盖、相关性、事实错误、未问内容与简洁性按事先定义量表评分；材料本身错误与生成捏造分别记 |
| 运行成本 | 实际 ms 的检索/模型/全链路时延，冷启动和预热分开，报告样本数与 P50/P95；索引时间、块数、存储、内存、上下文量、真实 usage/费用（可获得时） |
| 故障率 | 全部计划请求的失败、超时、未运行与成功数量；成功请求指标旁同时展示故障率，不能静默剔除失败美化结果 |

可答题遭系统故障时，另外给出按失败处理的端到端有效回答率，不用成功样本均值掩盖故障。小样本 P95 只作描述，不宣称稳定性能。缓存命中和真实调用、模型替身和外部模型、冷/热运行分开统计；没有真实 usage 就写未知。

当前页面的旧“Recall@5、MRR、引用准确率”必须标明旧口径，修复后给指标版本。旧报告不覆盖、不追溯伪造；不能将新旧口径直接画成提升曲线。

## 10. 发现问题后的处理顺序

1. 保存最小复现：用户角色、提问/资料、作用范围、版本、实际参数、期望与实际、错误码及脱敏证据。
2. 逐层定位：资料是否存在且发布 → 权限/版本允许列表 → 解析/切分 → 词项和向量 → 排名 → 门控 → 上下文选择 → 模型覆盖判断 → 引用保存 → 前端呈现。不要看到拒答就先降阈值。
3. 对可稳定复现的问题补有意义的失败回归测试；模型不确定问题用固定替身验证控制流，另保留真实失败样本，不用替身宣称效果改善。
4. 一次修复一类原因，运行受影响测试、相关回归和必要构建。只有跨模块变化才扩到全套，不无目的反复执行昂贵测试。
5. 比较基线与修改结果，包括变好的与变差的题；修复要解释为何可推广，不能靠题目白名单、固定答案或放开所有门控。
6. 更新问题状态、真实证据和剩余风险。修复无收益或使满意的基线退步时，恢复本轮自己修改的具体内容；不能整目录覆盖用户修改。

P0：越权、数据损失、密钥泄露、错误来源混用等先处理。P1：无关回答、有资料却漏检/误拒、指标失真。P2：非阻塞体验、性能或新能力。优先级必须结合真实影响，不能把所有潜在风险定为 P0。

交 Astra 的材料应包含：问题 ID、最小样本、配置/数据 hash、涉及代码、测试结果、已尝试方案及未决选择。此前审查覆盖部分词法/契约问题，**不等于最新跨知识库实现已经完成 Astra 专项审查**。
