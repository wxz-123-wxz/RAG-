## 2. 可行性结论

业务开发基础环境基本具备：JDK 17、Maven、Node/npm、Python、Git 和 MySQL 已安装。当前 MySQL 服务可连接但项目库尚未创建；全局 Python 缺少 FastAPI/Uvicorn，D 盘项目虚拟环境尚未创建；主要缺口还包括 Elasticsearch、运行中的 Docker 引擎，以及生成/向量模型所需硬件信息。

在未确认物理内存和 GPU 前，不应承诺本地部署大型生成模型。架构保留两条路径：

1. **开发优先路径**：Embedding 和 Reranker 选择可在 CPU 或现有硬件运行的小型中文模型；生成模型使用用户获准的兼容接口。
2. **离线答辩路径**：若后续确认显卡和内存足够，再验证本地小参数 Qwen 模型；否则准备固定演示结果/录屏，但现场回答仍明确标注服务状态。

两条路径共用模型适配接口，因此不会要求修改核心业务模块。

## 3. 版本建议（待联网和用户许可后锁定）

| 组件 | 建议策略 | 原因 |
|---|---|---|
| Spring Boot | 选择支持 JDK 17 的稳定 3.x 版本并在构建文件锁定 | 避免浮动依赖 |
| Vue / Vite | 选择与 Node 20/22 LTS 明确兼容的稳定版本 | Node 24 可能超出部分插件验证范围 |
| Python | 项目独立 Python 3.11 环境，位置放在 D 盘项目目录 | 多数 ML 库支持更成熟，且不污染全局 Anaconda |
| MySQL | 使用现有 8.0.40 | 满足 JSON、窗口函数和事务需求 |
| Elasticsearch | 选择当前稳定且支持 `dense_vector`/kNN 的同一主版本 | 同时承载 BM25 和向量检索 |
| Redis | 首期可选；若使用则换为受支持版本或容器 | 本机 3.0.504 已明显过旧 |
| 模型 | 通过原型测试后锁定具体名称、版本、维度和许可证 | 避免硬件不适配与实验不可复现 |

“建议版本”不等于已安装版本。所有下载必须经用户允许，目标缓存、虚拟环境、Docker 数据或模型目录应明确位于 `D:\毕业设计` 或用户指定的 D 盘路径。

## 4. 建议目录规划

```text
D:\毕业设计\RAG软件工程知识问答系统\
├─ frontend\               # Vue 前端（实现阶段）
├─ backend\                # Spring Boot（实现阶段）
├─ rag-service\            # FastAPI（实现阶段）
├─ deploy\                 # Compose/Nginx（实现阶段）
├─ docs\                   # 设计与测试资料
├─ data\
│  ├─ evaluation\          # 标准问题和实验结果
│  ├─ source-documents\    # 经授权的课程资料
│  ├─ uploads\             # 开发期上传文件
│  └─ elasticsearch\       # 如采用容器，映射到此处
└─ .runtime\               # 经允许后放 Python 环境/模型缓存，不提交 Git
```

项目配置应显式设置缓存和数据目录，不能假定默认用户目录。实现前还需确认 Maven/npm/pip/Docker 的缓存是否会写入 C 盘；若会，需在用户许可后调整到 D 盘。

## 5. 分阶段验证建议

### 阶段 A：最小基础设施

- 启动 Docker Desktop 或选择直接安装的服务方式。
- 验证 MySQL 项目账号、字符集和时区。
- 启动 Elasticsearch，验证中文文本索引和向量字段。
- 建立 Python 3.11 环境并运行一个固定文本的 Embedding 冒烟测试。

### 阶段 B：RAG 原型

- 用 2 至 3 份小文档验证 PDF/DOCX/MD/TXT 抽取。
- 比较 400/600/800 字符切片及 80/100/120 重叠。
- 在 10 至 20 道开发题上验证 BM25、向量、RRF 和重排链路。
- 测量内存、索引大小和单题阶段耗时，再决定具体模型。

### 阶段 C：完整开发与实验

- 固化版本和配置样例，完成业务模块、权限和异常处理。
- 扩展到 20 至 40 份授权资料和 100 道标准题。
- 在固定环境执行功能、安全、效果和性能测试。

## 6. 当前阻塞项

开始业务编码前需要用户确认学校与指导教师约束；开始依赖安装和模型下载前需要用户明确允许，并确定所有写入 D 盘的缓存/数据目录。以下信息也需要补充：

- 物理内存、CPU 型号、是否有非 NVIDIA GPU。
- 学校是否允许外部模型接口及答辩现场联网。
- 可用课程资料及其授权状态。
- 指导教师是否要求固定 Elasticsearch、模型或部署方式。

在这些信息确认前，可以完成代码骨架和纯单元测试设计，但不应宣称模型部署或指标目标已经可达。
