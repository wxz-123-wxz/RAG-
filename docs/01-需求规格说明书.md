# 软件需求规格说明书

版本：0.1（需求基线草案）  
状态：待用户与指导教师评审

## 1. 引言

### 1.1 目的

本文定义系统边界、角色、功能需求、非功能需求和验收标准，作为后续设计、开发、测试及论文撰写的共同依据。

### 1.2 产品范围

系统以经过授权的软件工程课程资料为知识源。学生在指定知识库内提问，系统通过检索增强生成答案并展示证据；教师维护知识库与评测题；系统管理员维护用户、模型配置和审计信息。

系统不是开放领域搜索引擎，不训练基础大模型，不保证替代教师判断。知识库缺少可靠证据时必须拒答。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 知识库 | 一门课程或一个受控主题下的文档、索引和权限集合 |
| 文档版本 | 同一逻辑文档的一次内容快照 |
| 文档片段 | 含正文、章节、页码等元数据的最小检索单元 |
| 混合检索 | BM25 关键词检索与向量检索结果融合 |
| 重排序 | 使用独立模型对候选片段与问题的相关性重新评分 |
| 引用 | 回答所依据的文档片段及其来源元数据 |
| 拒答 | 证据不足时不生成事实性答案，并给出固定说明 |

## 2. 用户与权限

| 角色 | 主要能力 | 数据边界 |
|---|---|---|
| 学生 | 登录、问答、查看本人会话、查看引用、提交反馈 | 已发布且有权访问的知识库；本人会话与反馈 |
| 教师/知识库管理员 | 管理被授权知识库、文档、处理任务和评测题，查看知识库统计 | 仅被授权管理的知识库 |
| 系统管理员 | 用户与角色、全局配置、模型配置、审计和全局统计 | 全系统 |

## 3. 功能需求

需求优先级：P0 为首期验收必需，P1 为应实现，P2 为可延期增强。

### 3.1 认证与权限

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| FR-AUTH-001 | 用户使用账号和密码登录、刷新令牌并退出 | P0 | 密码不明文存储；退出后刷新令牌失效 |
| FR-AUTH-002 | 后端对所有受保护接口执行身份和角色校验 | P0 | 未登录返回 401，越权返回 403 |
| FR-AUTH-003 | 教师按知识库授权，不能管理未授权知识库 | P0 | 使用数据权限测试验证 |
| FR-AUTH-004 | 用户只能访问自己的私有会话 | P0 | 修改资源 ID 仍不能越权读取 |
| FR-AUTH-005 | 登录、配置变更、文档变更等关键操作写入审计日志 | P0 | 日志包含操作者、动作、对象、时间和结果 |
| FR-AUTH-006 | 管理员可启停账号、重置密码和分配角色 | P1 | 被停用账号无法登录 |

### 3.2 知识库与文档

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| FR-KB-001 | 教师创建、编辑、发布、下架被授权知识库 | P0 | 下架后学生不可新建问答，历史引用仍可审计 |
| FR-KB-002 | 知识库配置课程、简介、访问范围和检索参数 | P0 | 参数校验且变更可追踪 |
| FR-DOC-001 | 上传 PDF、DOCX、MD、TXT 文档 | P0 | 格式、大小、空文件和恶意文件名校验 |
| FR-DOC-002 | 基于 SHA-256 识别同知识库内重复内容 | P0 | 重复文件返回冲突信息，不重复处理 |
| FR-DOC-003 | 保存逻辑文档与版本，支持查看版本列表 | P0 | 新版本不覆盖旧版本记录 |
| FR-DOC-004 | 教师可删除未发布文档、下架已发布文档 | P0 | 索引与业务状态最终一致，操作有审计记录 |
| FR-DOC-005 | 展示上传、排队、解析、切片、索引、成功、失败状态 | P0 | 状态流转可查询，失败包含脱敏原因 |
| FR-DOC-006 | 失败任务可重试，同一版本同时最多一个活动任务 | P0 | 重复点击不会创建并行任务 |

### 3.3 文档处理与检索

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| FR-ING-001 | 抽取正文并保留文档名、章节、页码等来源元数据 | P0 | 引用可定位原文；无页码格式标记为空 |
| FR-ING-002 | 清洗空白和噪声，按章节与长度切片并保留重叠 | P0 | 边界测试通过，片段不得为空 |
| FR-ING-003 | Embedding、Reranker、Chat Model 使用可替换接口 | P0 | 可通过配置替换实现，不改业务调用方 |
| FR-RET-001 | 支持向量、混合、混合加重排三种检索配置 | P0 | 同一评测题集可分别运行并保存配置 |
| FR-RET-002 | 支持按知识库、发布状态和文档权限过滤 | P0 | 不返回其他知识库或下架内容 |
| FR-RET-003 | 融合结果去重并记录候选、分数、名次和耗时 | P0 | 检索日志可用于离线分析 |

### 3.4 问答、引用与反馈

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| FR-QA-001 | 用户选择知识库后创建会话并单轮或多轮提问 | P0 | 问答和上下文持久化 |
| FR-QA-002 | 多轮问题可结合有限历史改写为独立检索问题 | P1 | 保存原问题和改写问题，便于审计 |
| FR-QA-003 | 回答严格基于选定证据，文档内提示注入不得改变系统规则 | P0 | 安全测试题不泄露提示词、不执行文档指令 |
| FR-QA-004 | 返回回答、状态、总耗时和引用列表 | P0 | 引用含文档、章节/页码、片段预览和关联编号 |
| FR-QA-005 | 证据分数或覆盖不足时返回固定拒答信息 | P0 | 知识库外题正确拒答率可评测 |
| FR-QA-006 | 用户可对回答重新生成，保留各版本 | P1 | 新版本不覆盖旧回答和引用 |
| FR-QA-007 | 用户可查看、重命名和删除自己的历史会话 | P0 | 删除采用逻辑删除或明确的数据保留策略 |
| FR-FB-001 | 用户可提交有帮助/无帮助和问题标签及补充意见 | P0 | 每个用户对一个回答保留一条当前反馈 |

### 3.5 统计、评测与运维

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| FR-STAT-001 | 展示热门问题、无答案问题、低评价回答、常引用文档 | P0 | 支持知识库和时间范围过滤 |
| FR-STAT-002 | 展示检索失败数、问答量和平均/分位响应时间 | P0 | 指标口径在界面和接口中一致 |
| FR-EVAL-001 | 教师录入、导入、编辑和停用标准问题 | P0 | 校验问题、标准答案、目标来源和拒答标记 |
| FR-EVAL-002 | 创建批量评测并冻结运行配置 | P0 | 每次运行保存切片、检索、模型和阈值配置快照 |
| FR-EVAL-003 | 计算 Recall@5、MRR、拒答率和响应时间 | P0 | 指标可由原始逐题结果复算 |
| FR-EVAL-004 | 人工录入回答正确性、完整性和引用准确性评分 | P0 | 保存评分人、时间和备注 |
| FR-EVAL-005 | 对比三种检索方案并导出原始结果 | P1 | 不自动编造人工评分或论文结论 |
| FR-OPS-001 | 上游服务异常时返回可理解错误并记录关联 ID | P0 | 不暴露堆栈、密钥或内部地址 |

## 4. 业务规则

1. 只有 `PUBLISHED` 知识库和文档可以被学生问答检索。
2. 同一知识库内相同 SHA-256 的有效文档版本视为重复。
3. 文档状态遵循 `UPLOADED -> QUEUED -> PARSING -> CHUNKING -> INDEXING -> READY`；任一步可进入 `FAILED`，失败后可重新排队。
4. 回答状态至少包括 `GENERATING`、`ANSWERED`、`REFUSED`、`FAILED`。
5. 引用必须关联生成时实际使用的片段，不能在回答生成后伪造匹配。
6. 删除知识库前必须先下架；业务记录原则上逻辑删除，原始文件清理采用受控任务。
7. 评测运行开始后配置快照不可修改；参数变更应创建新运行。
8. 模型密钥只通过环境变量或未提交配置注入，管理接口返回时必须脱敏。

## 5. 非功能需求

| 编号 | 类别 | 要求与验收方式 |
|---|---|---|
| NFR-SEC-001 | 安全 | 密码使用 BCrypt/Argon2；令牌有过期时间；文件名规范化；输入进行长度、类型和权限校验 |
| NFR-SEC-002 | 安全 | 防止水平/垂直越权；日志和接口不返回密钥、密码、完整系统提示词 |
| NFR-SEC-003 | 安全 | 文档文本视为不可信数据，与系统指令隔离；建立提示注入测试集 |
| NFR-PERF-001 | 性能 | 检索平均耗时目标 <=2 秒，普通问答目标 <=10 秒；只在注明环境、样本、并发和模型后报告实测值 |
| NFR-REL-001 | 可靠性 | 文档任务可重试且具幂等性；外部模型/搜索超时不产生残缺成功记录 |
| NFR-OBS-001 | 可观测性 | 请求带 traceId；记录阶段耗时、错误类别和关键业务事件，不记录敏感正文 |
| NFR-MNT-001 | 可维护性 | 前后端和 RAG 服务边界清晰；外部模型与存储通过接口适配；配置分环境管理 |
| NFR-UX-001 | 易用性 | 问答显示明确加载、拒答、失败和空状态；引用可直接定位原文 |
| NFR-COMP-001 | 兼容性 | 首期支持最新版 Chrome/Edge；服务端使用 UTF-8；处理常见中文文件名 |
| NFR-DATA-001 | 数据 | 数据库、索引和文件备份策略一致；删除和保留策略有文档说明 |

## 6. 数据与外部接口

- 业务数据：MySQL 8。
- 检索数据：Elasticsearch，保存片段文本、稀疏字段、向量和过滤元数据。
- 文件：开发期保存于项目配置指定的数据目录；生产部署可替换 MinIO。
- 缓存/限流：Redis 可选，但异步任务状态的唯一事实来源仍为数据库。
- 模型：Embedding、Reranker 和 Chat Model 均通过内部 RAG 接口调用，不向浏览器暴露密钥。

## 7. 首期验收条件

1. 三类角色的核心流程可在干净环境按部署文档复现。
2. 四类文档可上传、解析、切片、索引；异常文件有明确失败状态。
3. 可完成混合检索问答、引用查看、多轮会话、拒答和反馈。
4. 越权、未登录、重复上传、模型超时和搜索不可用测试通过。
5. 至少 100 道评测题可批量运行，指标由逐题结果计算并能复算。
6. 三种检索方案完成同题集对比，报告真实配置和数据，不预设结论。
7. 提供源代码、数据库迁移、环境配置示例、测试报告、部署说明和演示数据说明。

## 8. 需求追踪

测试用例 ID 将采用 `TC-<模块>-<序号>`，并在测试文档中关联本文件的需求编号。例如 `TC-AUTH-001 -> FR-AUTH-001`。任何 P0 需求变更必须同步更新用例、API、数据库和测试设计。
