## 3. 已完成的主要源码修改

### 3.1 相邻上下文与原文覆盖

- 检索结果支持相邻块上下文扩展，减少答案要点被分块边界截断的问题。
- 引用映射改为对应连续原文区间，降低引用点击后只看到孤立片段或错位文本的情况。
- 增加逐要点原文覆盖复核，答案中的关键要点需要能在保存的证据区间内回查。

### 3.2 检索和引用正确性

- 修复 B 树查询中误引 u.keys[0] 的问题，避免答案与引用指向错误概念。
- 修正常见毕业答辩问题的别名和解释型查询召回，包括缓存、死锁、虚拟内存、DNS、单一职责原则和折半查找等问法。
- 增加证据充足度相关诊断，区分有证据、证据不足和无证据等状态。

### 3.3 索引与并发安全

- 索引版本切换采用原子方式。
- 查询请求使用请求级索引快照，减少索引重建期间读请求跨版本混用的风险。
- 已针对重建并发场景做过专门回归，但仍应保留真实并发和超时风险测试结果，不把离线测试等同于生产级保证。

### 3.4 模型失败诊断

- 模型调用失败时增加诊断信息，包括 trace、status 和 reason 等字段。
- 前端出现“请求未完成 / 请求失败 / 生成模型调用失败，未生成可保存的回答”时，应优先依据诊断信息排查模型配置、模型服务可用性、超时、并发限流和返回格式，不要直接归因于检索无结果。

## 6. 尚存限制与风险

1. **二叉搜索树语义冲突**：资料中“每轮排除一半”的表述与二叉搜索树最坏可退化到 O(n) 存在冲突，需要人工决定修订资料或约束答案措辞。
2. **无正式准确率**：当前没有完整的人工金标准题集和双人复核结论。
3. **Embedding 基线**：当前主要仍是 hashing embedding 基线，不能描述成高质量真实语义向量模型的最终效果。
4. **无独立真实 Reranker**：尚未形成可对外声称的独立真实重排模型和正式阈值标定结果。
5. **文档解析范围有限**：PDF、DOCX 解析能力尚未完善。
6. **整体超时控制有限**：严格覆盖检索、重排、生成全链路的 wall-clock 超时尚未完全实现。
7. **引用不等于蕴含**：引用区间存在，只证明可以回查原文，不自动证明原文完整支持答案的全部语义。
8. **并发验证边界**：已有并发回归不能替代长时间压力、资源耗尽和异常恢复测试。

## 10. 建议的最终验收顺序

### T0：恢复和真实链路验收

1. 启动 MySQL、RAG、后端和前端，逐项记录健康检查结果。
2. 验证登录和基本页面加载。
3. 使用代表性题目完成真实问答、保存回答、历史列表读取和详情回查。
4. 点击每条引用，核对显示文本、连续原文区间、文档来源和坐标映射。
5. 验证死锁、TCP 握手、B 树、证据不足、无证据等典型场景。
6. 验证通用回答、历史记录和反馈流程，但不要恢复通用回答确认弹窗。
7. 保留所有失败样例及 trace/status/reason，不要只记录成功截图。

### T1：风险和质量复核

1. 完整运行 scripts/smoke/_model.py --context-regression 对应流程，保存真实结果。
2. 做语义边界、超时、并发查询与索引重建风险测试。
3. 人工复核 Luna 标记题和全部原始空命中题。
4. 如需发布指标，先建立人工金标准，再计算准确率、Recall、MRR 等指标。
5. 如时间允许，再接入真实 Embedding、真实 Reranker，并做参数和阈值对比实验。

### 毕业设计收口

1. 只修复影响演示、核心功能或报告真实性的明确问题。
2. 确保论文中对 Embedding、Reranker、准确率、解析格式、并发和超时能力的描述与实际系统一致。
3. 最后完成一次从启动到停机的演示彩排，并保存通过、失败和未测清单。
