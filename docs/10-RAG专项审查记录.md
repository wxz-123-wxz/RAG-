## 已确认

1. 索引请求改为 FastAPI 所需的 snake_case 字段；后端运行时测试验证 JSON 正文和内部令牌。
2. RRF 排名融合分数不再直接比较 0.05 阈值，避免分数上限约 0.0328 导致必然拒答。最新主题门控之后，VECTOR 检查哈希原始阈值；HYBRID 也允许 BM25 正分证据通过。RRF 零分通道不参与、相同分数同名次；混合查询可保留一个实际概念定义段落。均是未标定启发式，不是真实模型重排。
3. 空文档版本允许列表不再检索草稿。提问和重生成重新检查知识库可见性与发布状态，实际服务验证下架后两种入口均被阻止。
4. 引用必须来自允许的版本集合，通过 `document_version_id + chunk_no` 回查 MySQL，引用原文逐字一致才保存；标题、章节和页码也回查数据库。原文、索引与引用的真实闭环已验证。
5. 用户问答统一先检索再调用生成模型；显式生成请求不会悄悄退回原文模式。无证据在调用模型前拒答并返回空引用；历史 `extractive-no-llm` 记录仍可回看。
6. 模型缺配置、凭据错误、限流、超时和无效引用有明确错误码，不计为正确拒答。无效或缺失引用编号会使生成失败，不再静默删除编号后保存；生成失败实际测试确认事务回滚。
7. 问答与重生成传递回答模式并记录模型名；后端 HTTP 客户端使用配置的超时。页面拒答后清空上条回答的来源，提示调整问法或补充资料。
8. 文档 READY 才可发布，评测筛选状态修正为 READY；数据库消息版本字段和统计分组错误已在真实运行中修复。统计仍读取实际消息、反馈和引用。

## 分级响应的实际实现

有检索片段时，原文模式仍只显示原文；生成模式要求 JSON `coverage + claims[text,citations] + missing_aspects`。完整/部分是模型自报覆盖范围，每条已答要点必须有有效证据编号，未覆盖内容分开说明；不展示置信百分比。结构错误、缺引用和截断响应均拒绝保存，不能降级成自由回答。

所有已保存知识库回答（完整、部分、拒答、历史原文）均可通过“大模型回答”按钮直接调用 `general-answer`，点击请求携带 `confirm=true`，无二次确认弹窗。仍检查会话归属、知识库发布状态和源回答状态，GENERAL 不链式触发。只发原问题，不发送文档或原始历史；输出无知识库引用，`answer_origin=GENERAL`，统计排除，评测仍固定原文模式。最新 Java 34 项、本地替身跨服务 19 项及真实浏览器验证通过。领域硬分类、联网搜索和真正的置信度标定均未实现。

## 真实性限制

1. `hashing-tfidf-baseline` 是确定性哈希向量，仅用于链路和零依赖测试，不是中文语义 Embedding。
2. 当前 `HYBRID_RERANK` 的代码路径执行 BM25+向量 RRF，尚未接入独立 Reranker，名称不能被解释为已经完成重排实验。
3. 评测 Recall@5/MRR 使用最终引用与参考文档名或证据文本的词法匹配，接近 hit@5，不等于完整检索金标准召回；引用结构准确率不等于语义支持。当前评测固定原文模式，不能代表生成质量。
4. `0.12`、`0.05` 等阈值是未经标定的开发值，必须用真实 Embedding 的独立验证集重新标定。两题烟测的 1.0 或取整后 0 ms 不得解释为正式准确率或性能结论。
5. 评测接口目前同步调用 RAG。低并发开发可用，但高延迟模型会占用 Web 请求线程和数据库事务；性能测试后再决定是否改为异步任务或 SSE。
