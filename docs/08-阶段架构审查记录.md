## 2. 已修复问题

### R-001 RAG 引用主键不一致

**问题**：RAG 索引内部使用哈希 chunk ID，后端最初尝试将该字符串解析为 MySQL `BIGINT`，真实问答会在保存引用时失败。  
**修复**：回答引用同时返回 `document_version_id` 和 `chunk_no`；后端使用版本与序号查询 MySQL 片段主键，再保存引用快照。  
**残余要求**：必须通过真实 RAG 服务集成测试验证版本/序号映射，不能只依赖单元测试。

### R-002 文档任务提交时序

**问题**：上传事务未提交前启动异步处理，可能读取不到刚写入的元数据。  
**修复**：使用事务同步 `afterCommit` 调度；重试同样在提交后调度；任务以条件更新保证只启动一次。

## 3. 当前架构风险

1. 首版任务处理只直接读取 TXT/Markdown；PDF/DOCX 解析器尚未接入，任务会明确失败而不是伪成功。
2. MySQL、RAG 服务、模型服务之间没有统一的端到端测试环境；需要 Docker/服务启动后验证。
3. 会话历史目前只读取最近用户问题，尚未持久化完整角色交替上下文摘要；多轮问答效果仍待验证。
4. 统计和评测数据表、批量评测编排和仪表盘接口已完成代码实现；仍需真实 MySQL/RAG 服务做端到端验证。
5. Spring Boot 的同步 `RestClient` 调用占用请求线程；首期低并发可接受，若性能测试不达标再改为异步任务或 SSE。
